## Section 1: Week 2 Summary

### Day 8 -- Lists & List Comprehensions

- Lists are ordered, mutable sequences: the default container for collections of items.
- Comprehension syntax: `[expr for x in iterable if cond]`.
- Generator expressions `(expr for x in iterable)` save memory for single-pass processing.

### Day 9 -- Tuples & Named Tuples

- Tuples are immutable, hashable sequences -- ideal for fixed records and function return values.
- `typing.NamedTuple` adds field names and type hints for self-documenting code.
- Use `_replace()` to create modified copies.

### Day 10 -- Dictionaries

- Dicts map hashable keys to values with O(1) average lookup.
- `defaultdict` auto-creates missing entries; `Counter` counts occurrences.
- Dict comprehensions: `{k: v for k, v in items if cond}`.
- Merge with `|` (Python 3.9+).

### Day 11 -- Sets & Frozen Sets

- Sets store unique elements with O(1) membership testing.
- Operations: union `|`, intersection `&`, difference `-`, symmetric difference `^`.
- `frozenset` is immutable and hashable -- usable as a dict key.

### Day 12 -- Iterators & Generators

- The iterator protocol: `__iter__()` and `__next__()`.
- Generator functions use `yield`; generator expressions use `()`.
- `itertools` essentials: `chain`, `islice`, `count`, `cycle`.
- Generators are single-use and lazy -- constant memory usage.

### Day 13 -- Collections Module & Data Structure Choices

- `deque`: O(1) append/pop on both ends; `maxlen` for sliding windows.
- `OrderedDict`: order-aware equality, `move_to_end()`.
- `ChainMap`: layered lookup across multiple dicts.
- Always match the data structure to the problem's access pattern.

## Section 2: Data Structure Decision Tree

When you face a new problem, work through these questions:

```
1. Do I need key-value pairs?
   YES --> dict / defaultdict / Counter / OrderedDict / ChainMap
   NO  --> go to 2

2. Do I need uniqueness or fast membership testing?
   YES --> set / frozenset
   NO  --> go to 3

3. Will the collection change (add/remove items)?
   YES --> go to 4
   NO  --> tuple / NamedTuple

4. Do I need fast append/pop from both ends?
   YES --> deque
   NO  --> list

5. Is the data too large for memory or only needs one pass?
   YES --> generator (function or expression)
   NO  --> materialise with list/set/dict
```

## Section 3: Quick Reference Table

| Structure | Ordered | Mutable | Unique | Hashable | Best For |
|---|---|---|---|---|---|
| `list` | Yes | Yes | No | No | General-purpose sequences |
| `tuple` | Yes | No | No | Yes* | Fixed records, dict keys |
| `dict` | Yes (3.7+) | Yes | Keys | No | Key-value mappings |
| `set` | No | Yes | Yes | No | Membership, dedup |
| `frozenset` | No | No | Yes | Yes | Immutable sets, dict keys |
| `deque` | Yes | Yes | No | No | Queues, sliding windows |
| `NamedTuple` | Yes | No | No | Yes* | Self-documenting records |
| generator | -- | -- | -- | No | Lazy iteration |

\* Hashable only if all contained elements are hashable.
