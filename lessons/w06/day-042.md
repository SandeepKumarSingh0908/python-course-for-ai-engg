## Week 6 Summary

### Day 36 -- Matplotlib Fundamentals

- The OO interface: `fig, ax = plt.subplots()`
- Core plot types: `ax.plot()`, `ax.scatter()`, `ax.bar()`, `ax.hist()`, `ax.pie()`
- Subplots: `fig, axes = plt.subplots(nrows, ncols)`
- Always label axes, add titles, and use `plt.tight_layout()`
- Save with `fig.savefig("file.png", dpi=150, bbox_inches="tight")`

### Day 37 -- Seaborn & Advanced Visualization

- Figure-level: `relplot`, `catplot`, `displot` (create their own figure)
- Axes-level: `scatterplot`, `boxplot`, `violinplot`, `histplot` (accept `ax=`)
- `sns.pairplot()` for quick EDA across all feature pairs
- `sns.heatmap()` for correlation matrices and confusion matrices
- Themes: `sns.set_theme(style="whitegrid")`, palettes: `palette="viridis"`

### Day 38 -- Working with REST APIs

- HTTP methods: GET (read), POST (create), PUT (replace), DELETE (remove)
- `requests.get(url, params=, headers=, timeout=)`
- `requests.post(url, json=, headers=)` -- auto-sets Content-Type
- Always call `response.raise_for_status()`
- Use `requests.Session()` for connection reuse and shared headers
- Retry with exponential backoff or `urllib3.util.retry.Retry`
- Pagination: offset-based, cursor-based, or Link-header

### Day 39 -- Databases with Python

- `sqlite3.connect()`, `cursor.execute()`, `cursor.fetchall()`, `conn.commit()`
- Parameterized queries: `execute("SELECT * WHERE id = ?", (val,))`
- Context managers: `with sqlite3.connect(path) as conn:`
- `pd.read_sql_query()` for direct DataFrame loading
- SQLAlchemy ORM: `Base`, `Column`, `Session`, `query().filter().all()`

### Day 40 -- Concurrency & Async

- GIL: threads work for I/O-bound; processes for CPU-bound
- `ThreadPoolExecutor(max_workers=N)` with `executor.map()` or `submit()`
- `ProcessPoolExecutor` for CPU-heavy work; guard with `if __name__ == "__main__"`
- `asyncio.run(main())`, `await asyncio.gather(*tasks)`
- `aiohttp` for async HTTP; `asyncio.Semaphore` for rate limiting

### Day 41 -- Testing with pytest

- Test files: `test_*.py`, functions: `test_*`
- `assert`, `pytest.approx()`, `pytest.raises()`
- Fixtures in `conftest.py`; scopes: function, class, module, session
- `@pytest.mark.parametrize` for multi-input tests
- `unittest.mock.patch` and `monkeypatch` for mocking
- `pytest --cov` for coverage reporting

## Practice Problems

### Problem 1: Matplotlib (5 min)

Write code that creates a figure with two subplots side by side:
- Left: a histogram of 500 samples from a normal distribution (mean=0, std=1)
- Right: a scatter plot of those same values (index vs. value)

Both plots should have titles, axis labels, and a shared color scheme.

<details>
<summary>Solution</summary>

```python
import matplotlib.pyplot as plt
import numpy as np

np.random.seed(42)
data = np.random.normal(0, 1, 500)

fig, axes = plt.subplots(1, 2, figsize=(12, 4))

axes[0].hist(data, bins=30, color="steelblue", edgecolor="white")
axes[0].set_title("Distribution")
axes[0].set_xlabel("Value")
axes[0].set_ylabel("Count")

axes[1].scatter(range(len(data)), data, alpha=0.5, s=10, color="steelblue")
axes[1].set_title("Values Over Index")
axes[1].set_xlabel("Index")
axes[1].set_ylabel("Value")

plt.tight_layout()
plt.show()
```

</details>

### Problem 2: Seaborn (5 min)

Using `sns.load_dataset("tips")`, create a single figure containing:
- A violin plot of `total_bill` by `day`
- A correlation heatmap of all numeric columns

Use axes-level functions so both live in one figure.

<details>
<summary>Solution</summary>

```python
import seaborn as sns
import matplotlib.pyplot as plt

tips = sns.load_dataset("tips")
fig, axes = plt.subplots(1, 2, figsize=(14, 5))

sns.violinplot(data=tips, x="day", y="total_bill", palette="muted", ax=axes[0])
axes[0].set_title("Total Bill by Day")

corr = tips.select_dtypes(include="number").corr()
sns.heatmap(corr, annot=True, fmt=".2f", cmap="coolwarm", ax=axes[1])
axes[1].set_title("Correlation Matrix")

plt.tight_layout()
plt.show()
```

### Problem 3: REST API (5 min)

Write a function `fetch_user_posts(user_id: int) -> list[str]` that:
1. Calls `https://jsonplaceholder.typicode.com/posts?userId={user_id}`
2. Returns a list of post titles
3. Handles timeouts and HTTP errors gracefully (return an empty list on failure)

<details>
<summary>Solution</summary>

```python
import requests

def fetch_user_posts(user_id: int) -> list[str]:
    try:
        response = requests.get(
            "https://jsonplaceholder.typicode.com/posts",
            params={"userId": user_id},
            timeout=10
        )
        response.raise_for_status()
        return [post["title"] for post in response.json()]
    except (requests.exceptions.RequestException, KeyError):
        return []

titles = fetch_user_posts(1)
print(f"User 1 has {len(titles)} posts")
for t in titles[:3]:
    print(f"  - {t}")
```

</details>

### Problem 4: Database (5 min)

Write a function that:
1. Creates an in-memory SQLite database
2. Creates a `scores` table with columns: `student TEXT`, `subject TEXT`, `score REAL`
3. Inserts 5 rows
4. Returns the average score per subject as a dict

<details>
<summary>Solution</summary>

```python
import sqlite3

def get_averages() -> dict:
    with sqlite3.connect(":memory:") as conn:
        conn.execute("""
            CREATE TABLE scores (
                student TEXT, subject TEXT, score REAL
            )
        """)
        conn.executemany(
            "INSERT INTO scores VALUES (?, ?, ?)",
            [
                ("Alice", "math", 92),
                ("Bob", "math", 85),
                ("Alice", "science", 88),
                ("Bob", "science", 91),
                ("Charlie", "math", 78),
            ]
        )
        conn.commit()
        cursor = conn.execute(
            "SELECT subject, AVG(score) FROM scores GROUP BY subject"
        )
        return {row[0]: round(row[1], 1) for row in cursor.fetchall()}

print(get_averages())
# {'math': 85.0, 'science': 89.5}
```

</details>

### Problem 5: Testing (5 min)

Given this function:

```python
def classify_score(score: float) -> str:
    if score >= 90:
        return "A"
    elif score >= 80:
        return "B"
    elif score >= 70:
        return "C"
    else:
        return "F"
```

Write a parametrized test that checks all four grade boundaries plus edge cases.

<details>
<summary>Solution</summary>

```python
import pytest

@pytest.mark.parametrize("score, expected", [
    (95, "A"),
    (90, "A"),     # boundary
    (89.9, "B"),   # just below A
    (80, "B"),     # boundary
    (79, "C"),     # just below B
    (70, "C"),     # boundary
    (69.9, "F"),   # just below C
    (0, "F"),
    (100, "A"),
])
def test_classify_score(score, expected):
    assert classify_score(score) == expected
```

</details>

### Problem 6: Concurrency (5 min)

Explain in one sentence each:
1. Why threads do not speed up CPU-bound Python code.
2. What `asyncio.gather()` does differently from calling coroutines sequentially.
3. When you would use `ProcessPoolExecutor` instead of `ThreadPoolExecutor`.

<details>
<summary>Answers</summary>

1. The GIL allows only one thread to execute Python bytecode at a time, so threads
   take turns on the CPU rather than running in parallel.
2. `asyncio.gather()` schedules all coroutines to run concurrently on the event loop,
   so I/O waits overlap; calling them sequentially would wait for each to finish
   before starting the next.
3. Use `ProcessPoolExecutor` when your task is CPU-bound (numerical computation,
   data transformation) because each process has its own GIL and runs on a separate
   CPU core.

</details>
