## Section 1: if / elif / else

The basic building block of decision-making in Python.

```python
score = 85

if score >= 90:
    grade = "A"
elif score >= 80:
    grade = "B"
elif score >= 70:
    grade = "C"
elif score >= 60:
    grade = "D"
else:
    grade = "F"

print(f"Score {score} -> Grade {grade}")   # Score 85 -> Grade B
```

### Key rules

- Indentation defines the block (4 spaces by convention).
- `elif` and `else` are optional.
- Python evaluates conditions top to bottom and takes the **first** branch that matches.
- There is no `switch` statement in Python prior to 3.10 (use `match-case` instead).

### Multiple conditions

```python
age = 25
has_license = True
has_insurance = True

if age >= 18 and has_license and has_insurance:
    print("Cleared to drive")
elif age >= 18 and has_license:
    print("Need insurance")
else:
    print("Not eligible")
```

### Nested if (use sparingly)

```python
user_role = "admin"
is_active = True

if is_active:
    if user_role == "admin":
        print("Full access granted")
    else:
        print("Limited access granted")
else:
    print("Account disabled")
```

Deeply nested ifs become hard to read. Prefer early returns in functions (covered in Day 5) or flatten with `and`.

## Section 2: Truthiness and Falsy Values

Python evaluates any object in a boolean context. You do not always need explicit comparisons.

### Falsy values (evaluate to `False`)

```python
falsy_values = [False, 0, 0.0, 0j, "", [], (), {}, set(), None, range(0)]

for val in falsy_values:
    assert not val, f"{val!r} should be falsy"
    # All pass
```

### Everything else is truthy

```python
truthy_values = [True, 1, -1, 3.14, "hello", [0], (0,), {"key": "val"}, {0}]

for val in truthy_values:
    assert val, f"{val!r} should be truthy"
    # All pass
```

### Idiomatic Python

```python
items = []

# Verbose (non-Pythonic)
if len(items) == 0:
    print("No items")

# Pythonic
if not items:
    print("No items")

# Checking for None specifically
result = None
if result is None:
    print("No result yet")
```

**Important distinction:** `if not x` catches `None`, `0`, `""`, `[]`, and `False`. If you only want to check for `None`, use `if x is None`.

## Section 3: match-case (Python 3.10+)

Structural pattern matching is Python's version of switch-case, but far more powerful.

### Basic value matching

```python
status_code = 404

match status_code:
    case 200:
        print("OK")
    case 301:
        print("Redirect")
    case 404:
        print("Not Found")
    case 500:
        print("Server Error")
    case _:
        print(f"Unknown status: {status_code}")
```

The `_` is the wildcard pattern -- it matches anything.

### Matching with guards

```python
temperature = 102.5

match temperature:
    case temp if temp < 95:
        print("Hypothermia risk")
    case temp if temp <= 99.5:
        print("Normal")
    case temp if temp <= 103:
        print("Fever")
    case _:
        print("Seek emergency care")
```

### Matching structure (destructuring)

This is where match-case really shines -- extracting data from structures.

```python
command = ("move", "north", 5)

match command:
    case ("quit",):
        print("Exiting")
    case ("move", direction, distance):
        print(f"Moving {direction} by {distance}")
    case ("attack", target):
        print(f"Attacking {target}")
    case _:
        print("Unknown command")

# Output: Moving north by 5
```

### AI use case: routing model responses

```python
def handle_response(response):
    match response:
        case {"status": "success", "predictions": predictions}:
            return predictions
        case {"status": "error", "message": msg}:
            print(f"Model error: {msg}")
            return None
        case {"status": "pending"}:
            print("Still processing...")
            return None
        case _:
            print(f"Unexpected response format: {response}")
            return None

# Test it
result = handle_response({"status": "success", "predictions": [0.8, 0.2]})
print(result)  # [0.8, 0.2]
```

## Section 4: Ternary Expressions

A conditional expression in a single line. Use it when the logic is simple.

```python
# Syntax: value_if_true if condition else value_if_false

age = 20
category = "adult" if age >= 18 else "minor"
print(category)  # adult
```

### Practical examples

```python
# Clamping a value
score = 105
clamped = min(max(score, 0), 100)  # 100

# Choosing a label
prediction = 0.73
label = "positive" if prediction >= 0.5 else "negative"

# Handling missing data
raw_value = ""
clean_value = raw_value if raw_value else "N/A"
```

### Do NOT nest ternaries

```python
# This is legal but unreadable -- avoid it
x = 15
result = "high" if x > 20 else "medium" if x > 10 else "low"

# Instead, use if/elif/else
if x > 20:
    result = "high"
elif x > 10:
    result = "medium"
else:
    result = "low"
```

## Section 5: Worked Example -- Data Validation Pipeline

You receive raw records and need to validate them before they enter your training dataset.

```python
def validate_record(record):
    """Validate a single data record for ML training.
    
    Returns (is_valid, cleaned_record_or_error_message).
    """
    # Check required fields exist
    required_fields = ["feature_1", "feature_2", "label"]
    for field in required_fields:
        if field not in record:
            return False, f"Missing required field: {field}"

    # Validate feature values are numeric
    for field in ["feature_1", "feature_2"]:
        value = record[field]
        if not isinstance(value, (int, float)):
            return False, f"Non-numeric value in {field}: {value!r}"
        if value != value:  # NaN check (NaN != NaN is True)
            return False, f"NaN detected in {field}"

    # Validate label
    valid_labels = {0, 1}
    if record["label"] not in valid_labels:
        return False, f"Invalid label: {record['label']}"

    # All checks passed
    cleaned = {
        "feature_1": float(record["feature_1"]),
        "feature_2": float(record["feature_2"]),
        "label": int(record["label"]),
    }
    return True, cleaned


# Test with various records
test_records = [
    {"feature_1": 1.5, "feature_2": 2.3, "label": 1},
    {"feature_1": "bad", "feature_2": 2.3, "label": 0},
    {"feature_1": 1.0, "label": 1},
    {"feature_1": 1.0, "feature_2": 3.0, "label": 2},
]

for i, record in enumerate(test_records):
    is_valid, result = validate_record(record)
    status = "PASS" if is_valid else "FAIL"
    print(f"Record {i}: [{status}] {result}")
```

Expected output:
```
Record 0: [PASS] {'feature_1': 1.5, 'feature_2': 2.3, 'label': 1}
Record 1: [FAIL] Non-numeric value in feature_1: 'bad'
Record 2: [FAIL] Missing required field: feature_2
Record 3: [FAIL] Invalid label: 2
```

## Common Mistakes

- **Using `==` to compare with `None`.** Always use `is None` or `is not None`. Custom classes can override `__eq__` and make `==` behave unexpectedly.
- **Confusing `if not x` with `if x is None`.** The former catches all falsy values (0, empty string, empty list). The latter catches only `None`.
- **Forgetting the colon.** Every `if`, `elif`, `else`, `case` line ends with `:`. This becomes muscle memory quickly.
- **Over-nesting.** More than 2-3 levels of nesting is a code smell. Refactor into helper functions or use early returns.
- **Using `match-case` on Python < 3.10.** Check your Python version with `python --version`. If below 3.10, use if/elif chains instead.
