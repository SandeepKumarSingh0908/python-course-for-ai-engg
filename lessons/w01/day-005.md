## Section 1: Defining Functions

```python
def greet(name):
    """Return a greeting string."""
    return f"Hello, {name}!"

message = greet("Ada")
print(message)   # Hello, Ada!
```

### Multiple return values

Python functions can return multiple values as a tuple.

```python
def min_max(numbers):
    """Return the minimum and maximum of a list."""
    return min(numbers), max(numbers)

lo, hi = min_max([4, 1, 7, 2, 9])
print(f"Min: {lo}, Max: {hi}")   # Min: 1, Max: 9
```

### Returning None

If a function has no `return` statement, or has a bare `return`, it returns `None`.

```python
def print_header(title):
    print(f"=== {title} ===")
    # implicitly returns None

result = print_header("Report")
print(result)   # None
```

### Early returns

Use early returns to handle edge cases first. This keeps your main logic at a low indentation level.

```python
def safe_divide(a, b):
    """Divide a by b, returning None if b is zero."""
    if b == 0:
        return None
    return a / b

print(safe_divide(10, 3))   # 3.333...
print(safe_divide(10, 0))   # None
```

## Section 2: Parameters and Arguments

### Positional and keyword arguments

```python
def train_model(data, epochs, learning_rate):
    print(f"Training on {len(data)} samples, "
          f"{epochs} epochs, lr={learning_rate}")

# Positional
train_model([1, 2, 3], 10, 0.01)

# Keyword (order does not matter)
train_model(learning_rate=0.01, data=[1, 2, 3], epochs=10)

# Mixed (positional must come first)
train_model([1, 2, 3], epochs=10, learning_rate=0.01)
```

### Default values

```python
def train_model(data, epochs=10, learning_rate=0.001, verbose=False):
    if verbose:
        print(f"Config: epochs={epochs}, lr={learning_rate}")
    # ... training logic

# Use defaults
train_model(my_data)

# Override some defaults
train_model(my_data, epochs=50, verbose=True)
```

### The mutable default argument trap

This is one of Python's most infamous gotchas. Default arguments are evaluated **once** when the function is defined, not each time it is called.

```python
# BUG: the same list is shared across all calls
def append_to(item, target=[]):
    target.append(item)
    return target

print(append_to(1))   # [1]
print(append_to(2))   # [1, 2]  -- NOT [2]!
print(append_to(3))   # [1, 2, 3]  -- the list accumulates

# FIX: use None as the default
def append_to(item, target=None):
    if target is None:
        target = []
    target.append(item)
    return target

print(append_to(1))   # [1]
print(append_to(2))   # [2]  -- correct!
```

**Rule:** Never use a mutable object (`list`, `dict`, `set`) as a default argument. Use `None` and create the mutable object inside the function.

## Section 3: *args and **kwargs

### *args -- variable positional arguments

`*args` collects extra positional arguments into a tuple.

```python
def compute_mean(*values):
    """Compute the mean of any number of values."""
    if not values:
        return 0.0
    return sum(values) / len(values)

print(compute_mean(10, 20, 30))      # 20.0
print(compute_mean(5))                # 5.0
print(compute_mean())                 # 0.0
```

### **kwargs -- variable keyword arguments

`**kwargs` collects extra keyword arguments into a dictionary.

```python
def create_config(**kwargs):
    """Create a configuration dictionary from keyword arguments."""
    config = {
        "epochs": 10,
        "learning_rate": 0.001,
        "batch_size": 32,
    }
    config.update(kwargs)   # Override defaults with provided values
    return config

config = create_config(epochs=50, dropout=0.3)
print(config)
# {'epochs': 50, 'learning_rate': 0.001, 'batch_size': 32, 'dropout': 0.3}
```

### Combining everything

The order of parameters must be: regular, `*args`, keyword-only, `**kwargs`.

```python
def flexible(required, *args, keyword_only=True, **kwargs):
    print(f"required: {required}")
    print(f"args: {args}")
    print(f"keyword_only: {keyword_only}")
    print(f"kwargs: {kwargs}")

flexible("hello", 1, 2, 3, keyword_only=False, extra="value")
# required: hello
# args: (1, 2, 3)
# keyword_only: False
# kwargs: {'extra': 'value'}
```

### Unpacking with * and **

```python
def add(a, b, c):
    return a + b + c

values = [1, 2, 3]
print(add(*values))       # 6 -- unpacks the list into positional args

params = {"a": 10, "b": 20, "c": 30}
print(add(**params))      # 60 -- unpacks the dict into keyword args
```

## Section 4: Scope -- the LEGB Rule

When Python encounters a variable name, it searches for it in this order:

1. **L**ocal -- inside the current function
2. **E**nclosing -- in the enclosing function (for nested functions)
3. **G**lobal -- at the module level
4. **B**uilt-in -- Python's built-in names (`print`, `len`, `range`, etc.)

```python
x = "global"

def outer():
    x = "enclosing"
    
    def inner():
        x = "local"
        print(x)        # local
    
    inner()
    print(x)            # enclosing

outer()
print(x)                # global
```

### The `global` and `nonlocal` keywords

```python
counter = 0

def increment():
    global counter       # Without this, assigning to counter creates a local
    counter += 1

increment()
increment()
print(counter)           # 2
```

```python
def make_counter():
    count = 0
    
    def increment():
        nonlocal count   # Refers to the enclosing scope's count
        count += 1
        return count
    
    return increment

counter = make_counter()
print(counter())   # 1
print(counter())   # 2
print(counter())   # 3
```

**Best practice:** Avoid `global`. Pass values in as arguments and return results. Global mutable state makes code hard to test and debug.

## Section 5: Docstrings

Docstrings are the standard way to document functions in Python. They are accessible via `help()` and by IDEs.

```python
def normalize(values, method="min-max"):
    """Normalize a list of numeric values.
    
    Args:
        values: A list of numbers to normalize.
        method: The normalization method. Either "min-max" (default)
                or "z-score".
    
    Returns:
        A new list of normalized values.
    
    Raises:
        ValueError: If the method is not recognized.
        ValueError: If the list is empty.
    
    Example:
        >>> normalize([1, 2, 3, 4, 5])
        [0.0, 0.25, 0.5, 0.75, 1.0]
    """
    if not values:
        raise ValueError("Cannot normalize an empty list")
    
    if method == "min-max":
        lo, hi = min(values), max(values)
        spread = hi - lo
        if spread == 0:
            return [0.0] * len(values)
        return [(v - lo) / spread for v in values]
    elif method == "z-score":
        mean = sum(values) / len(values)
        std = (sum((v - mean) ** 2 for v in values) / len(values)) ** 0.5
        if std == 0:
            return [0.0] * len(values)
        return [(v - mean) / std for v in values]
    else:
        raise ValueError(f"Unknown method: {method}")
```

Use Google-style, NumPy-style, or Sphinx-style docstrings consistently across your project. The example above uses Google style.

## Section 6: Worked Example -- Building a Metrics Module

```python
def accuracy(y_true, y_pred):
    """Compute classification accuracy.
    
    Args:
        y_true: List of true labels.
        y_pred: List of predicted labels.
    
    Returns:
        Float between 0.0 and 1.0.
    """
    if len(y_true) != len(y_pred):
        raise ValueError("Lists must have the same length")
    if not y_true:
        raise ValueError("Lists must not be empty")
    
    correct = sum(1 for t, p in zip(y_true, y_pred) if t == p)
    return correct / len(y_true)


def confusion_counts(y_true, y_pred, positive_label=1):
    """Compute TP, FP, TN, FN for binary classification.
    
    Args:
        y_true: List of true labels (0 or 1).
        y_pred: List of predicted labels (0 or 1).
        positive_label: Which label is the positive class.
    
    Returns:
        Tuple of (tp, fp, tn, fn).
    """
    tp = fp = tn = fn = 0
    for true, pred in zip(y_true, y_pred):
        if pred == positive_label and true == positive_label:
            tp += 1
        elif pred == positive_label and true != positive_label:
            fp += 1
        elif pred != positive_label and true != positive_label:
            tn += 1
        else:
            fn += 1
    return tp, fp, tn, fn


def precision_recall(y_true, y_pred, positive_label=1):
    """Compute precision and recall.
    
    Returns:
        Tuple of (precision, recall). Returns 0.0 for undefined cases.
    """
    tp, fp, tn, fn = confusion_counts(y_true, y_pred, positive_label)
    precision = tp / (tp + fp) if (tp + fp) > 0 else 0.0
    recall = tp / (tp + fn) if (tp + fn) > 0 else 0.0
    return precision, recall


# Test it
y_true = [1, 1, 0, 1, 0, 0, 1, 0]
y_pred = [1, 0, 0, 1, 0, 1, 1, 0]

print(f"Accuracy: {accuracy(y_true, y_pred):.2%}")
tp, fp, tn, fn = confusion_counts(y_true, y_pred)
print(f"TP={tp}, FP={fp}, TN={tn}, FN={fn}")
p, r = precision_recall(y_true, y_pred)
print(f"Precision: {p:.2%}, Recall: {r:.2%}")
```

## Common Mistakes

- **Mutable default arguments.** Use `None` as the default for list, dict, and set parameters. Create the mutable object inside the function body.
- **Forgetting to return a value.** If your function computes something, make sure it returns it. Printing is not returning.
- **Modifying arguments in place unexpectedly.** If you receive a list and mutate it, the caller's list changes too. Make a copy if the caller should not see changes.
- **Too many parameters.** If a function takes more than 5-6 parameters, consider grouping them into a dictionary or a dataclass.
- **Using `global` when you should pass arguments.** Functions should receive inputs via parameters and produce outputs via return values. Avoid side effects through global state.
