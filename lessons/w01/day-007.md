## Quick Reference: Week 1 at a Glance

### Day 1 -- Variables, Data Types & Type Casting

- Core types: `int`, `float`, `str`, `bool`, `None`
- Inspect with `type()` and `isinstance()`
- Cast with `int()`, `float()`, `str()`, `bool()`
- `bool("False")` is `True` (any non-empty string is truthy)
- Compare to `None` with `is`, not `==`

### Day 2 -- Operators & Expressions

- Arithmetic: `+`, `-`, `*`, `/` (true div), `//` (floor div), `%`, `**`
- Comparison: `==`, `!=`, `<`, `>`, `<=`, `>=` (chaining works: `0 <= x <= 1`)
- Logical: `and`, `or`, `not` (short-circuit evaluation)
- Bitwise: `&`, `|`, `^` (needed for pandas/NumPy boolean indexing)
- Walrus operator: `:=` (assign inside expressions)
- When in doubt about precedence, use parentheses

### Day 3 -- Control Flow

- `if`/`elif`/`else` for branching
- `match-case` for structural pattern matching (Python 3.10+)
- Falsy values: `False`, `0`, `0.0`, `""`, `[]`, `()`, `{}`, `set()`, `None`
- Ternary: `value_if_true if condition else value_if_false`
- Use `if not x` to check for emptiness; use `if x is None` to check specifically for None

### Day 4 -- Loops & Iteration

- `for` with `range()`, `enumerate()`, `zip()`
- `while` for indefinite iteration (always ensure termination)
- `break` exits the loop; `continue` skips to the next iteration
- `else` on a loop runs only if no `break` occurred
- Avoid nested loops on large data; use sets, dicts, or vectorized operations

### Day 5 -- Functions

- `def`, parameters (positional, keyword, default), `return`
- `*args` (tuple of extra positionals), `**kwargs` (dict of extra keywords)
- Mutable default trap: never use `[]` or `{}` as a default; use `None`
- LEGB scope: Local, Enclosing, Global, Built-in
- Write docstrings for every non-trivial function

### Day 6 -- Strings & String Methods

- f-strings for formatting: `f"{value:.2f}"`, `f"{value:.2%}"`
- Slicing: `s[start:stop:step]`, reverse with `s[::-1]`
- Key methods: `split()`, `join()`, `strip()`, `replace()`, `find()`, `startswith()`
- Raw strings (`r"..."`) for regex and file paths
- `re.search()` for first match, `re.findall()` for all matches
- Always specify `encoding="utf-8"` when opening files

## Practice Problems

Work through these problems in a file called `gate_review.py`. Each problem intentionally combines concepts from multiple days.

### Problem 1: Type-Safe Aggregator

Write a function `safe_aggregate(values)` that takes a list of mixed values and returns a dictionary with:
- `"sum"`: the sum of all numeric values (int and float, but not bool)
- `"count"`: the number of numeric values
- `"mean"`: the mean of the numeric values (or `None` if count is 0)
- `"skipped"`: a list of all non-numeric values that were skipped

```python
data = [10, "hello", 3.5, None, True, 20, "world", 7.5, False, 0]
result = safe_aggregate(data)
# Expected:
# sum = 41.0  (10 + 3.5 + 20 + 7.5 + 0)
# count = 5
# mean = 8.2
# skipped = ['hello', None, True, 'world', False]
```

Hint: `isinstance(value, bool)` must be checked **before** `isinstance(value, int)` because `bool` is a subclass of `int`.

### Problem 2: Mini Gradebook

Write a program that processes student records.

```python
students = [
    {"name": "Alice", "scores": [85, 92, 78, 90, 88]},
    {"name": "Bob", "scores": [72, 68, 74, 71]},
    {"name": "Charlie", "scores": [95, 98, 92, 97, 100, 94]},
    {"name": "Diana", "scores": []},
    {"name": "Eve", "scores": [55, 62, 58]},
]
```

For each student:
1. Compute the average score (handle empty score lists gracefully)
2. Assign a letter grade: A (>=90), B (>=80), C (>=70), D (>=60), F (<60)
3. Determine pass/fail status ("pass" if grade is D or above)

Print a formatted report:
```
Name         Avg   Grade  Status
---------------------------------------
Alice       86.60  B      pass
Bob         71.25  C      pass
Charlie     96.00  A      pass
Diana         N/A  N/A    N/A
Eve         58.33  F      fail
```

Use f-string formatting to align the columns.

### Problem 4: Convergence Simulator

Write a function `simulate_training(initial_loss, decay_rate, target_loss, max_epochs)` that:
- Starts with `initial_loss`
- Each epoch multiplies the loss by `decay_rate` (e.g., 0.9)
- Stops when loss drops below `target_loss` or `max_epochs` is reached
- Returns a list of tuples: `[(epoch, loss), ...]`
- Uses the `else` clause on the while loop to detect if max_epochs was reached without convergence

```python
history = simulate_training(
    initial_loss=5.0,
    decay_rate=0.85,
    target_loss=0.01,
    max_epochs=100
)
for epoch, loss in history:
    bar = "#" * int(loss * 10)
    print(f"Epoch {epoch:3d}: {loss:.4f} {bar}")
```

### Problem 5: Config Parser & Validator

Combine string processing with control flow and functions. Write a function `parse_and_validate(config_text)` that:

1. Parses a config string (skip comments and blank lines, split on `=`)
2. Auto-detects types: integers, floats, booleans (`true`/`false`), or strings
3. Validates against these rules:
   - `learning_rate` must be between 0 and 1
   - `epochs` must be a positive integer
   - `batch_size` must be a power of 2
   - `model_name` must not be empty
4. Returns `(config_dict, errors_list)`

```python
config = """
# Training config
model_name = transformer-v2
learning_rate = 1.5
epochs = -10
batch_size = 48
dropout = 0.3
"""

config_dict, errors = parse_and_validate(config)
print("Config:", config_dict)
print("Errors:", errors)
# Errors should include: learning_rate out of range, epochs not positive,
# batch_size not a power of 2
```

## Tips for the Gate Assessment

1. **Read the problem fully before coding.** Identify which concepts it tests. Most problems combine 2-3 topics.
2. **Start with the simplest case.** Get basic functionality working, then handle edge cases.
3. **Use descriptive variable names.** `avg_score` is better than `a`. The assessor (and future you) should understand the code at a glance.
4. **Handle edge cases.** Empty lists, None values, zero division, invalid input -- these are what separate solid code from fragile code.
5. **Test as you go.** Print intermediate results. Do not write 50 lines and then run for the first time.
6. **Write functions, not scripts.** Break your solution into small, testable functions. This is the pattern you will follow in real ML work.
