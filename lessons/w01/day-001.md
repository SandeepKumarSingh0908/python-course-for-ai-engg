Whether you are feeding features into a model, parsing JSON from an API, or reading a CSV into a DataFrame, you need to know what type your data is and how to convert between types reliably. Mismatched types are one of the most common sources of silent bugs in data pipelines.

## Section 1: Core Data Types

Python is **dynamically typed** -- you do not declare the type of a variable. The interpreter figures it out at runtime based on the value you assign.

```python
age = 30            # int
temperature = 98.6  # float
name = "Ada"        # str
is_active = True    # bool
result = None       # NoneType
```

### Integers (`int`)

Integers have arbitrary precision in Python. There is no overflow.

```python
big_number = 10 ** 100   # a googol -- no problem
count = -42
binary_val = 0b1010      # 10 in binary
hex_val = 0xFF           # 255 in hex
```

### Floats (`float`)

Floats use IEEE 754 double-precision (64-bit). They can represent very large and very small numbers but have limited precision.

```python
pi = 3.141592653589793
tiny = 1e-10
huge = 2.5e8   # 250,000,000.0

# The classic gotcha:
print(0.1 + 0.2)          # 0.30000000000000004
print(0.1 + 0.2 == 0.3)   # False
```

When exact decimal arithmetic matters (finance, certain metrics), use `decimal.Decimal`.

### Strings (`str`)

Strings are immutable sequences of Unicode characters.

```python
greeting = "Hello, world"
multiline = """This spans
multiple lines."""
escaped = "She said \"hi\""
```

### Booleans (`bool`)

`bool` is a subclass of `int`. `True` is `1` and `False` is `0`.

```python
print(True + True)    # 2
print(False * 100)    # 0
print(isinstance(True, int))  # True
```

### None

`None` is Python's null value. It is a singleton -- there is exactly one `None` object.

```python
x = None
print(x is None)      # True  (use 'is', not '==')
print(type(x))         # <class 'NoneType'>
```

## Section 2: Inspecting Types

### `type()` -- returns the exact type

```python
print(type(42))         # <class 'int'>
print(type(3.14))       # <class 'float'>
print(type("hello"))    # <class 'str'>
print(type(True))       # <class 'bool'>
print(type(None))       # <class 'NoneType'>
```

### `isinstance()` -- checks against a type or tuple of types

`isinstance` is generally preferred in production code because it respects inheritance.

```python
value = 42
print(isinstance(value, int))            # True
print(isinstance(value, (int, float)))   # True -- checks against multiple types
print(isinstance(True, int))             # True -- bool is a subclass of int
```

## Section 3: Type Casting

Casting converts a value from one type to another. It creates a **new** object; it does not mutate the original.

```python
# str -> int
user_input = "42"
number = int(user_input)       # 42

# float -> int (truncates, does NOT round)
print(int(3.9))                # 3
print(int(-3.9))               # -3

# int -> float
print(float(7))                # 7.0

# int -> str
print(str(100))                # "100"

# str -> float
print(float("3.14"))           # 3.14

# Truthiness casting with bool()
print(bool(0))                 # False
print(bool(""))                # False
print(bool(None))              # False
print(bool(42))                # True
print(bool("anything"))        # True
```

### When casting fails

```python
int("hello")    # ValueError: invalid literal for int() with base 10: 'hello'
int("")          # ValueError
float("N/A")    # ValueError
```

Always validate or use try/except before casting untrusted data.

## Section 4: Dynamic Typing and Variable Naming

### Dynamic typing

A variable can be reassigned to a value of a different type at any time.

```python
x = 10       # int
x = "ten"    # now str -- Python does not complain
```

This flexibility is powerful but risky. In AI pipelines, an unexpected type change can propagate silently until it causes a crash far downstream. Type hints (covered later) help catch these issues early.

### Naming conventions (PEP 8)

```python
# Variables and functions: snake_case
learning_rate = 0.001
batch_size = 32

# Constants: UPPER_SNAKE_CASE
MAX_EPOCHS = 100
DEFAULT_SEED = 42

# Classes: PascalCase
# (covered in a later lesson)

# Private/internal: leading underscore
_internal_cache = {}

# Avoid: single letters (except loop vars), shadowing built-ins
# BAD: list = [1, 2, 3]   # shadows the built-in list()
```

## Section 5: Worked Example -- Cleaning a Data Record

Imagine you receive a record from a CSV file. Every value arrives as a string.

```python
raw_record = {
    "patient_id": "1042",
    "age": "67",
    "temperature": "98.6",
    "is_diabetic": "True",
    "notes": "  routine checkup  "
}

# Clean and cast
patient_id = int(raw_record["patient_id"])
age = int(raw_record["age"])
temperature = float(raw_record["temperature"])
is_diabetic = raw_record["is_diabetic"] == "True"  # safer than bool("True")
notes = raw_record["notes"].strip()

print(f"Patient {patient_id}: age={age}, temp={temperature}, "
      f"diabetic={is_diabetic}, notes='{notes}'")
# Patient 1042: age=67, temp=98.6, diabetic=True, notes='routine checkup'
```

Notice we did **not** use `bool("True")` because `bool("True")` returns `True`, but so does `bool("False")` -- any non-empty string is truthy.

## Common Mistakes

- **Using `bool()` to parse string booleans.** `bool("False")` is `True` because the string is non-empty. Compare against the literal string instead: `value == "True"`.
- **Assuming `int()` rounds.** `int(3.9)` is `3`, not `4`. Use `round()` if you need rounding.
- **Shadowing built-in names.** Writing `list = [1, 2, 3]` or `type = "admin"` breaks access to the built-in functions `list()` and `type()` in that scope.
- **Comparing to `None` with `==` instead of `is`.** Always use `x is None` or `x is not None`. The `==` operator can be overridden by classes.
- **Ignoring float precision.** Never compare floats with `==`. Use `math.isclose()` or a tolerance threshold.
