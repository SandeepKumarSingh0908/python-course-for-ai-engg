# Day 17 - Dunder Methods & Protocols

**Module:** Week 3 -- OOP, Modules & Packages | **Time:** ~60 min (35 read + 25 lab)

> Dunder (double-underscore) methods are how Python objects hook into the language itself.
> When you write `len(dataset)`, Python calls `dataset.__len__()`. When PyTorch's
> `DataLoader` indexes your dataset with `dataset[42]`, it calls `dataset.__getitem__(42)`.
> When `nn.Module` instances are called like functions (`model(input)`), Python calls
> `model.__call__()`. Mastering dunders lets you build objects that feel native to Python
> and integrate seamlessly with ML frameworks.

## Section 1: Representation -- `__repr__` and `__str__`

```python
class Tensor:
    def __init__(self, data: list[float], name: str = ""):
        self.data = data
        self.name = name

    def __repr__(self) -> str:
        """Unambiguous: for developers. Shows how to recreate the object."""
        return f"Tensor(data={self.data!r}, name={self.name!r})"

    def __str__(self) -> str:
        """Readable: for end users. Called by print()."""
        label = f"'{self.name}' " if self.name else ""
        return f"Tensor {label}[{len(self.data)} elements]"


t = Tensor([1.0, 2.0, 3.0], name="weights")

print(repr(t))  # Tensor(data=[1.0, 2.0, 3.0], name='weights')
print(str(t))   # Tensor 'weights' [3 elements]
print(t)         # Uses __str__: Tensor 'weights' [3 elements]

# In the REPL or debugger, __repr__ is used:
# >>> t
# Tensor(data=[1.0, 2.0, 3.0], name='weights')
```

**Best practice:** Always implement `__repr__`. If `__str__` is not defined, Python falls
back to `__repr__`. The `repr` should ideally be valid Python that could recreate the
object.

## Section 2: Comparison and Hashing -- `__eq__`, `__lt__`, `__hash__`

```python
from functools import total_ordering

@total_ordering  # fills in __le__, __gt__, __ge__ from __eq__ and __lt__
class ModelScore:
    """Wraps a model name and its evaluation metric."""

    def __init__(self, name: str, score: float):
        self.name = name
        self.score = score

    def __repr__(self):
        return f"ModelScore({self.name!r}, {self.score})"

    def __eq__(self, other):
        if not isinstance(other, ModelScore):
            return NotImplemented
        return self.score == other.score

    def __lt__(self, other):
        if not isinstance(other, ModelScore):
            return NotImplemented
        return self.score < other.score

    def __hash__(self):
        """Needed if you want to put these in sets or use as dict keys."""
        return hash((self.name, self.score))


scores = [
    ModelScore("random-forest", 0.89),
    ModelScore("xgboost", 0.92),
    ModelScore("logistic-reg", 0.85),
]

print(sorted(scores))         # sorted by score (uses __lt__)
# [ModelScore('logistic-reg', 0.85), ModelScore('random-forest', 0.89), ...]

print(max(scores))            # ModelScore('xgboost', 0.92)

# Usable in sets
score_set = {ModelScore("a", 0.9), ModelScore("b", 0.9)}
print(len(score_set))         # 1 -- because __eq__ says they're equal
```

### Why return `NotImplemented`?

Returning `NotImplemented` (not raising `NotImplementedError`) tells Python to try the
other operand's method. This enables interoperation with different types.

## Section 3: Container Protocol -- `__len__`, `__getitem__`, `__contains__`

This is the protocol that makes PyTorch's `Dataset` work.

```python
class TextDataset:
    """A dataset of text samples with labels, following the PyTorch pattern."""

    def __init__(self, texts: list[str], labels: list[int]):
        if len(texts) != len(labels):
            raise ValueError("texts and labels must have the same length")
        self.texts = texts
        self.labels = labels

    def __len__(self) -> int:
        """len(dataset) returns the number of samples."""
        return len(self.texts)

    def __getitem__(self, index: int) -> dict:
        """dataset[i] returns the i-th sample as a dict."""
        if isinstance(index, slice):
            return [
                {"text": t, "label": l}
                for t, l in zip(self.texts[index], self.labels[index])
            ]
        return {"text": self.texts[index], "label": self.labels[index]}

    def __contains__(self, text: str) -> bool:
        """'some text' in dataset checks if the text exists."""
        return text in self.texts

    def __repr__(self):
        return f"TextDataset(n={len(self)}, labels={set(self.labels)})"


ds = TextDataset(
    texts=["great movie", "terrible film", "loved it", "waste of time"],
    labels=[1, 0, 1, 0],
)

print(len(ds))          # 4
print(ds[0])            # {'text': 'great movie', 'label': 1}
print(ds[1:3])          # [{'text': 'terrible film', ...}, {'text': 'loved it', ...}]
print("loved it" in ds) # True

# Works with iteration (Python uses __getitem__ with incrementing index)
for sample in ds:
    print(sample["text"], "->", sample["label"])
```

### `__iter__` for explicit iteration

If you want more control than `__getitem__`-based iteration:

```python
class BatchIterator:
    """Yields batches from a dataset."""

    def __init__(self, dataset: TextDataset, batch_size: int = 2):
        self.dataset = dataset
        self.batch_size = batch_size

    def __iter__(self):
        for i in range(0, len(self.dataset), self.batch_size):
            yield self.dataset[i : i + self.batch_size]

    def __len__(self):
        import math
        return math.ceil(len(self.dataset) / self.batch_size)


loader = BatchIterator(ds, batch_size=2)
for batch in loader:
    print(batch)
```

## Section 4: Arithmetic -- `__add__`, `__mul__`, and Friends

```python
class Vector:
    """A simple numeric vector with element-wise operations."""

    def __init__(self, data: list[float]):
        self.data = data

    def __repr__(self):
        return f"Vector({self.data})"

    def __add__(self, other):
        """v1 + v2: element-wise addition."""
        if isinstance(other, Vector):
            if len(self.data) != len(other.data):
                raise ValueError("Vectors must have the same length")
            return Vector([a + b for a, b in zip(self.data, other.data)])
        if isinstance(other, (int, float)):
            return Vector([a + other for a in self.data])
        return NotImplemented

    def __radd__(self, other):
        """Handles: 5 + vector (when int doesn't know how to add a Vector)."""
        return self.__add__(other)

    def __mul__(self, other):
        """v * scalar: scalar multiplication."""
        if isinstance(other, (int, float)):
            return Vector([a * other for a in self.data])
        if isinstance(other, Vector):
            # dot product
            return sum(a * b for a, b in zip(self.data, other.data))
        return NotImplemented

    def __rmul__(self, other):
        return self.__mul__(other)

    def __neg__(self):
        return Vector([-a for a in self.data])


v1 = Vector([1.0, 2.0, 3.0])
v2 = Vector([4.0, 5.0, 6.0])

print(v1 + v2)        # Vector([5.0, 7.0, 9.0])
print(v1 + 10)        # Vector([11.0, 12.0, 13.0])
print(v1 * 3)         # Vector([3.0, 6.0, 9.0])
print(3 * v1)         # Vector([3.0, 6.0, 9.0])  -- uses __rmul__
print(v1 * v2)        # 32.0  (dot product)
print(-v1)            # Vector([-1.0, -2.0, -3.0])
```

## Section 5: Callable Objects -- `__call__`

This is how PyTorch's `nn.Module` works: instances are called like functions.

```python
class Activation:
    """A callable activation function with configurable parameters."""

    def __init__(self, func_name: str = "relu", alpha: float = 0.01):
        self.func_name = func_name
        self.alpha = alpha
        self.call_count = 0

    def __call__(self, x: float) -> float:
        self.call_count += 1
        if self.func_name == "relu":
            return max(0.0, x)
        elif self.func_name == "leaky_relu":
            return x if x > 0 else self.alpha * x
        elif self.func_name == "sigmoid":
            import math
            return 1.0 / (1.0 + math.exp(-x))
        raise ValueError(f"Unknown activation: {self.func_name}")

    def __repr__(self):
        return f"Activation({self.func_name!r})"


relu = Activation("relu")
leaky = Activation("leaky_relu", alpha=0.1)

# Call instances like functions
print(relu(5.0))       # 5.0
print(relu(-3.0))      # 0.0
print(leaky(-3.0))     # -0.3

# They maintain state
print(relu.call_count) # 2

# They work with map and other higher-order functions
values = [-2, -1, 0, 1, 2]
print(list(map(relu, values)))   # [0.0, 0.0, 0.0, 1.0, 2.0]
```

### Why `__call__` matters in ML

```python
class SimpleLayer:
    """Mimics how nn.Module layers work."""

    def __init__(self, weights: list[float], bias: float):
        self.weights = weights
        self.bias = bias

    def __call__(self, inputs: list[float]) -> float:
        """Forward pass: dot product + bias."""
        return sum(w * x for w, x in zip(self.weights, inputs)) + self.bias


layer = SimpleLayer(weights=[0.5, -0.3, 0.8], bias=0.1)
output = layer([1.0, 2.0, 3.0])  # 0.5*1 + (-0.3)*2 + 0.8*3 + 0.1 = 2.4
print(output)  # 2.5
```

## Common Mistakes

1. **Confusing `__repr__` and `__str__`** -- `__repr__` is for developers (show in debugger),
   `__str__` is for users (show in `print()`). Always implement `__repr__` first.

2. **Raising `NotImplementedError` instead of returning `NotImplemented`** -- in comparison
   and arithmetic methods, return the singleton `NotImplemented` to let Python try the
   other operand. `NotImplementedError` is for abstract methods.

3. **Forgetting `__hash__` when defining `__eq__`** -- in Python 3, defining `__eq__`
   automatically sets `__hash__` to `None`, making instances unhashable. Define `__hash__`
   if you need your objects in sets or as dict keys.

4. **Mutable objects as dict keys** -- if your `__hash__` depends on mutable data, the
   hash can change after insertion, silently breaking the dict. Only hash immutable fields.

5. **Missing `__radd__`/`__rmul__`** -- without these, `5 + vector` fails even though
   `vector + 5` works. The `r` (right) variants handle the case where the left operand
   doesn't know how to add your type.
