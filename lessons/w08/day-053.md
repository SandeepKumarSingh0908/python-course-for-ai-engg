> Retrieval-Augmented Generation (RAG) is the most widely deployed LLM application pattern. Instead of relying solely on the model's training data, RAG retrieves relevant documents at query time and injects them into the prompt. This grounds the model in real data, reduces hallucination, and lets you build Q&A systems over your own documents. This lesson walks through every component of a RAG pipeline -- from loading documents to generating answers.

## Section 1: RAG Architecture

RAG has two phases: **offline indexing** and **online query**.

```
OFFLINE (index time):
  Documents -> Chunk -> Embed -> Store in Vector DB

ONLINE (query time):
  User Query -> Embed -> Retrieve top-k chunks -> Build prompt -> LLM -> Answer
```

### Why RAG?

- **Knowledge cutoff** -- Models only know what they were trained on. RAG adds current data.
- **Hallucination** -- Without source material, models confidently invent facts. RAG grounds answers in real documents.
- **Privacy** -- Your proprietary data never enters model training. It is only used at query time.
- **Cost** -- Cheaper than fine-tuning. You update the document index, not the model.

## Section 3: Chunking Strategies

Documents are too long to embed whole. Chunking splits them into pieces that fit the embedding model and capture meaningful units of information.

### Fixed-Size Chunking

The simplest approach: split every N characters with overlap.

```python
def chunk_fixed_size(
    text: str,
    chunk_size: int = 500,
    overlap: int = 100,
) -> list[str]:
    """Split text into fixed-size chunks with overlap."""
    chunks = []
    start = 0
    while start < len(text):
        end = start + chunk_size
        chunks.append(text[start:end])
        start = end - overlap  # slide back by overlap amount
    return chunks


text = "A" * 1200
chunks = chunk_fixed_size(text, chunk_size=500, overlap=100)
print(f"Text length: {len(text)}, Chunks: {len(chunks)}")
# Text length: 1200, Chunks: 3
```

### Sentence-Based Chunking

Preserves sentence boundaries for more coherent chunks.

```python
import re


def chunk_by_sentences(
    text: str,
    max_sentences: int = 5,
    overlap_sentences: int = 1,
) -> list[str]:
    """Split text into chunks of N sentences with overlap."""
    # Simple sentence splitting (for production, use spaCy or nltk)
    sentences = re.split(r"(?<=[.!?])\s+", text.strip())

    chunks = []
    start = 0
    while start < len(sentences):
        end = min(start + max_sentences, len(sentences))
        chunk = " ".join(sentences[start:end])
        chunks.append(chunk)
        start = end - overlap_sentences

    return chunks
```

### Recursive Character Chunking

Tries to split on natural boundaries (paragraphs, then sentences, then words) to keep semantic units together.

```python
def chunk_recursive(
    text: str,
    chunk_size: int = 500,
    overlap: int = 100,
    separators: list[str] | None = None,
) -> list[str]:
    """Recursively split text on a hierarchy of separators."""
    if separators is None:
        separators = ["\n\n", "\n", ". ", " ", ""]

    # Base case: text fits in one chunk
    if len(text) <= chunk_size:
        return [text] if text.strip() else []

    # Try each separator in order
    for sep in separators:
        if sep in text:
            parts = text.split(sep)
            chunks = []
            current = ""
            for part in parts:
                candidate = current + sep + part if current else part
                if len(candidate) <= chunk_size:
                    current = candidate
                else:
                    if current:
                        chunks.append(current.strip())
                    current = part
            if current:
                chunks.append(current.strip())
            return [c for c in chunks if c]

    # Fallback to fixed-size
    return chunk_fixed_size(text, chunk_size, overlap)
```

### Choosing Chunk Size

| Chunk size | Pros | Cons |
|---|---|---|
| Small (200-300 chars) | Precise retrieval, less noise | May lose context, more chunks to store |
| Medium (500-1000 chars) | Good balance | Most common starting point |
| Large (1000-2000 chars) | Rich context per chunk | May retrieve irrelevant content alongside relevant |

**Rule of thumb:** Start with 500-character chunks and 100-character overlap. Tune based on retrieval quality.

## Section 4: Indexing -- Embed and Store

```python
import chromadb
from chromadb.utils.embedding_functions import OpenAIEmbeddingFunction

# Or use the default (sentence-transformers) for free local embedding
# No embedding_function argument needed for the default.


def build_index(
    documents: list[dict],
    collection_name: str = "rag_docs",
    chunk_size: int = 500,
    chunk_overlap: int = 100,
) -> chromadb.Collection:
    """Chunk documents, embed them, and store in ChromaDB."""
    client = chromadb.Client()

    # Delete if exists (for re-indexing)
    try:
        client.delete_collection(collection_name)
    except Exception:
        pass

    collection = client.create_collection(name=collection_name)

    all_chunks = []
    all_ids = []
    all_metadatas = []

    for doc in documents:
        chunks = chunk_fixed_size(doc["text"], chunk_size, chunk_overlap)
        for i, chunk in enumerate(chunks):
            chunk_id = f"{doc['source']}::chunk_{i}"
            all_chunks.append(chunk)
            all_ids.append(chunk_id)
            all_metadatas.append({
                "source": doc["source"],
                "chunk_index": i,
            })

    # Add in batches (ChromaDB handles embedding automatically)
    batch_size = 100
    for i in range(0, len(all_chunks), batch_size):
        collection.add(
            ids=all_ids[i : i + batch_size],
            documents=all_chunks[i : i + batch_size],
            metadatas=all_metadatas[i : i + batch_size],
        )

    print(f"Indexed {collection.count()} chunks from {len(documents)} documents")
    return collection
```

## Section 5: Retrieval Strategies

### Top-K Retrieval

The simplest approach: return the K most similar chunks.

```python
def retrieve_top_k(
    collection: chromadb.Collection,
    query: str,
    k: int = 5,
) -> list[dict]:
    """Retrieve top-k most similar chunks."""
    results = collection.query(
        query_texts=[query],
        n_results=k,
    )

    retrieved = []
    for i in range(len(results["documents"][0])):
        retrieved.append({
            "id": results["ids"][0][i],
            "text": results["documents"][0][i],
            "distance": results["distances"][0][i],
            "metadata": results["metadatas"][0][i],
        })
    return retrieved
```

### Maximal Marginal Relevance (MMR)

Top-K can return redundant results. MMR balances relevance with diversity.

```python
import numpy as np


def mmr_rerank(
    query_embedding: np.ndarray,
    candidate_embeddings: np.ndarray,
    candidate_docs: list[dict],
    k: int = 5,
    lambda_param: float = 0.7,
) -> list[dict]:
    """Re-rank candidates using Maximal Marginal Relevance.

    lambda_param: 1.0 = pure relevance, 0.0 = pure diversity
    """
    selected_indices = []
    remaining = list(range(len(candidate_docs)))

    # Normalize embeddings
    query_norm = query_embedding / np.linalg.norm(query_embedding)
    cand_norms = candidate_embeddings / np.linalg.norm(
        candidate_embeddings, axis=1, keepdims=True
    )

    for _ in range(min(k, len(remaining))):
        best_score = -np.inf
        best_idx = -1

        for idx in remaining:
            # Relevance to query
            relevance = float(np.dot(query_norm, cand_norms[idx]))

            # Max similarity to already-selected docs
            if selected_indices:
                selected_embs = cand_norms[selected_indices]
                redundancy = float(np.max(np.dot(selected_embs, cand_norms[idx])))
            else:
                redundancy = 0.0

            score = lambda_param * relevance - (1 - lambda_param) * redundancy

            if score > best_score:
                best_score = score
                best_idx = idx

        selected_indices.append(best_idx)
        remaining.remove(best_idx)

    return [candidate_docs[i] for i in selected_indices]
```

## Section 6: Generation -- Context Injection

Now assemble the retrieved chunks into a prompt and call the LLM.

```python
from openai import OpenAI


def generate_answer(
    query: str,
    retrieved_chunks: list[dict],
    model: str = "gpt-4o",
    max_tokens: int = 512,
) -> str:
    """Generate an answer using retrieved context."""
    # Format the context
    context_parts = []
    for i, chunk in enumerate(retrieved_chunks, 1):
        source = chunk.get("metadata", {}).get("source", "unknown")
        context_parts.append(f"[Source {i}: {source}]\n{chunk['text']}")

    context = "\n\n".join(context_parts)

    system_prompt = """You are a helpful assistant that answers questions based on the provided context.
Rules:
- Only use information from the context below to answer the question.
- If the context does not contain enough information, say so honestly.
- Cite which source(s) you used in your answer (e.g., [Source 1])."""

    user_prompt = f"""Context:
{context}

Question: {query}

Answer:"""

    client = OpenAI()
    response = client.chat.completions.create(
        model=model,
        messages=[
            {"role": "system", "content": system_prompt},
            {"role": "user", "content": user_prompt},
        ],
        max_tokens=max_tokens,
        temperature=0.3,  # lower temperature for factual answers
    )

    return response.choices[0].message.content
```

## Section 7: Full Working RAG Pipeline

Putting it all together:

```python
class RAGPipeline:
    """A complete Retrieval-Augmented Generation pipeline."""

    def __init__(
        self,
        collection_name: str = "rag",
        chunk_size: int = 500,
        chunk_overlap: int = 100,
        top_k: int = 5,
        model: str = "gpt-4o",
    ):
        self.chunk_size = chunk_size
        self.chunk_overlap = chunk_overlap
        self.top_k = top_k
        self.model = model

        self.chroma_client = chromadb.Client()
        try:
            self.chroma_client.delete_collection(collection_name)
        except Exception:
            pass
        self.collection = self.chroma_client.create_collection(name=collection_name)

    def index_documents(self, documents: list[dict]):
        """Index documents (each with 'source' and 'text' keys)."""
        all_chunks, all_ids, all_metadatas = [], [], []

        for doc in documents:
            chunks = chunk_fixed_size(
                doc["text"], self.chunk_size, self.chunk_overlap
            )
            for i, chunk in enumerate(chunks):
                all_chunks.append(chunk)
                all_ids.append(f"{doc['source']}::chunk_{i}")
                all_metadatas.append({"source": doc["source"], "chunk_index": i})

        self.collection.add(
            ids=all_ids,
            documents=all_chunks,
            metadatas=all_metadatas,
        )
        print(f"Indexed {len(all_chunks)} chunks")

    def query(self, question: str) -> dict:
        """Run the full RAG pipeline: retrieve + generate."""
        # Retrieve
        retrieved = retrieve_top_k(self.collection, question, self.top_k)

        # Generate
        answer = generate_answer(question, retrieved, self.model)

        return {
            "question": question,
            "answer": answer,
            "sources": [
                {"text": r["text"][:200] + "...", "source": r["metadata"]["source"]}
                for r in retrieved
            ],
        }
```

## Common Mistakes

1. **Chunks too large** -- If you embed entire pages, retrieval becomes imprecise. You get lots of irrelevant text alongside the relevant part.
2. **No overlap** -- Without overlap, information at chunk boundaries is split across two chunks and may not be retrieved for either one.
3. **Trusting the model blindly** -- Always instruct the model to say "I don't know" when the context does not contain the answer. Without this, RAG still hallucinates.
4. **Not citing sources** -- The whole point of RAG is grounding. If you do not surface which chunks were used, you cannot verify answers.
5. **Re-embedding with a different model** -- Embeddings from different models live in different vector spaces. Always use the same model for indexing and querying.
