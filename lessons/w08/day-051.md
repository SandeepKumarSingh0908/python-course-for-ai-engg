As an AI engineer, you will spend far more time crafting, testing, and iterating on prompts than you will training models. This lesson teaches you to build prompts programmatically, use proven patterns like few-shot and chain-of-thought, and parse structured output reliably.

## Section 1: Prompt Templates

Hard-coding prompts breaks the moment requirements change. Use templates instead.

### f-string Templates

For simple cases, Python f-strings work fine:

```python
def summarize_prompt(text: str, max_sentences: int = 3) -> str:
    return f"""Summarize the following text in at most {max_sentences} sentences.
Be concise and preserve key facts.

Text:
{text}

Summary:"""


article = "Python was created by Guido van Rossum and first released in 1991..."
prompt = summarize_prompt(article, max_sentences=2)
print(prompt)
```

### String Template (Standard Library)

When you want to avoid accidental brace issues:

```python
from string import Template

template = Template("""You are a $role.
Analyze the following $doc_type and provide $output_format.

Document:
$document""")

prompt = template.substitute(
    role="senior code reviewer",
    doc_type="pull request",
    output_format="a bullet-point list of issues",
    document="def foo(x): return x+1",
)
```

### Jinja2 Templates

For complex prompts with conditionals, loops, and filters, use Jinja2:

```bash
pip install Jinja2
```

```python
from jinja2 import Template

template = Template("""You are a {{ role }}.

{% if context %}
Context:
{{ context }}
{% endif %}

{% if examples %}
Here are some examples:
{% for ex in examples %}
Input: {{ ex.input }}
Output: {{ ex.output }}
{% endfor %}
{% endif %}

Now process this input:
Input: {{ user_input }}
Output:""")

prompt = template.render(
    role="sentiment classifier",
    context="Classify the sentiment of product reviews.",
    examples=[
        {"input": "This product is amazing!", "output": "positive"},
        {"input": "Terrible quality, broke in a day.", "output": "negative"},
        {"input": "It works fine, nothing special.", "output": "neutral"},
    ],
    user_input="Best purchase I have ever made!",
)
print(prompt)
```

### Managing Prompts as Files

For larger projects, store prompts in separate files:

```python
from pathlib import Path
from jinja2 import Environment, FileSystemLoader

# prompts/
#   summarize.j2
#   classify.j2

env = Environment(loader=FileSystemLoader("prompts"))
template = env.get_template("summarize.j2")
prompt = template.render(text="...", max_sentences=3)
```

## Section 2: Few-Shot Prompting

Few-shot prompting gives the model examples of the task before the real input. This is the single most reliable way to steer model behavior.

```python
def build_few_shot_prompt(
    task_description: str,
    examples: list[dict[str, str]],
    user_input: str,
) -> list[dict[str, str]]:
    """Build a message list with few-shot examples.

    Each example dict has 'input' and 'output' keys.
    """
    messages = [
        {"role": "system", "content": task_description},
    ]

    for ex in examples:
        messages.append({"role": "user", "content": ex["input"]})
        messages.append({"role": "assistant", "content": ex["output"]})

    messages.append({"role": "user", "content": user_input})
    return messages


# Usage
messages = build_few_shot_prompt(
    task_description="You extract the programming language mentioned in a sentence. Respond with only the language name.",
    examples=[
        {"input": "I love building web apps with JavaScript.", "output": "JavaScript"},
        {"input": "Rust gives me confidence about memory safety.", "output": "Rust"},
        {"input": "Data scientists often prefer Python.", "output": "Python"},
    ],
    user_input="Go makes concurrency straightforward.",
)

# Pass `messages` to your API call
# response = client.chat.completions.create(model="gpt-4o", messages=messages)
```

**How many examples?** Start with 3-5. More examples cost more tokens. Add examples that cover edge cases you care about.

## Section 3: Chain-of-Thought Prompting

Chain-of-thought (CoT) prompting asks the model to reason step-by-step before answering. This dramatically improves accuracy on reasoning tasks.

### Basic CoT

```python
def cot_prompt(question: str) -> str:
    return f"""Solve the following problem step by step.
Show your reasoning before giving the final answer.

Problem: {question}

Step-by-step solution:"""


prompt = cot_prompt("If a train travels 120 km in 2 hours, then slows down and travels 90 km in 3 hours, what is its average speed for the entire trip?")
```

### Structured CoT with Explicit Sections

```python
def structured_cot_prompt(question: str) -> str:
    return f"""Analyze the following question carefully.

Question: {question}

Use this format:
GIVEN: List the known facts
REASONING: Show your step-by-step logic
ANSWER: State the final answer

Begin:"""
```

### CoT with Few-Shot Examples

The most powerful combination: show the model HOW to reason, then ask it to reason:

```python
COT_EXAMPLES = [
    {
        "input": "Is 127 prime?",
        "output": (
            "REASONING: I need to check divisibility by primes up to sqrt(127) ~ 11.3. "
            "Primes to check: 2, 3, 5, 7, 11. "
            "127 / 2 = 63.5 (not divisible). "
            "127 / 3 = 42.3 (not divisible). "
            "127 / 5 = 25.4 (not divisible). "
            "127 / 7 = 18.1 (not divisible). "
            "127 / 11 = 11.5 (not divisible). "
            "ANSWER: Yes, 127 is prime."
        ),
    },
]

messages = build_few_shot_prompt(
    task_description="You are a math tutor. Show your reasoning step by step.",
    examples=COT_EXAMPLES,
    user_input="Is 91 prime?",
)
```

## Section 4: Output Parsing

Models return strings. You need to convert those strings into data your program can use.

### JSON Mode (OpenAI)

```python
import json
from openai import OpenAI

client = OpenAI()

response = client.chat.completions.create(
    model="gpt-4o",
    response_format={"type": "json_object"},
    messages=[
        {
            "role": "system",
            "content": "Extract entities from the text. Respond with JSON: {\"people\": [...], \"places\": [...], \"dates\": [...]}",
        },
        {
            "role": "user",
            "content": "Marie Curie moved to Paris in 1891 to study at the Sorbonne.",
        },
    ],
)

entities = json.loads(response.choices[0].message.content)
print(entities)
# {"people": ["Marie Curie"], "places": ["Paris", "Sorbonne"], "dates": ["1891"]}
```

### Regex Extraction

When you cannot use JSON mode (or the model occasionally adds extra text), regex is your fallback:

```python
import re


def extract_answer(text: str) -> str | None:
    """Extract text after 'ANSWER:' marker."""
    match = re.search(r"ANSWER:\s*(.+?)(?:\n|$)", text, re.IGNORECASE)
    return match.group(1).strip() if match else None


def extract_code_block(text: str) -> str | None:
    """Extract content from a fenced code block."""
    match = re.search(r"```(?:\w+)?\n(.*?)```", text, re.DOTALL)
    return match.group(1).strip() if match else None


def extract_json_from_text(text: str) -> dict | None:
    """Find and parse the first JSON object in free text."""
    match = re.search(r"\{.*\}", text, re.DOTALL)
    if match:
        try:
            return json.loads(match.group())
        except json.JSONDecodeError:
            return None
    return None


# Test
raw_output = """Let me analyze this.

ANSWER: The average speed is 42 km/h.

Here is some extra commentary."""

print(extract_answer(raw_output))  # "The average speed is 42 km/h."
```

### Pydantic Validation

For production pipelines, validate parsed output against a schema:

```python
from pydantic import BaseModel, ValidationError
import json


class EntityExtraction(BaseModel):
    people: list[str]
    places: list[str]
    dates: list[str]


raw_json = '{"people": ["Marie Curie"], "places": ["Paris"], "dates": ["1891"]}'

try:
    result = EntityExtraction.model_validate_json(raw_json)
    print(result.people)   # ['Marie Curie']
    print(result.places)   # ['Paris']
except ValidationError as e:
    print(f"Output did not match schema: {e}")
```

## Section 5: System Prompts and Role Design

The system prompt defines the model's persona, constraints, and output format. Think of it as the model's job description.

### System Prompt Components

```python
def build_system_prompt(
    role: str,
    task: str,
    constraints: list[str],
    output_format: str,
) -> str:
    constraint_lines = "\n".join(f"- {c}" for c in constraints)
    return f"""You are {role}.

Your task: {task}

Constraints:
{constraint_lines}

Output format: {output_format}"""


system = build_system_prompt(
    role="a senior Python code reviewer",
    task="Review code snippets for bugs, style issues, and potential improvements",
    constraints=[
        "Focus on correctness first, style second",
        "Cite specific line numbers when pointing out issues",
        "Suggest fixes, do not just point out problems",
        "If the code is correct and clean, say so briefly",
    ],
    output_format="A numbered list of findings, each with severity (HIGH/MEDIUM/LOW)",
)
```

### Role Patterns for Common AI Applications

```python
# Chatbot: friendly, stays on topic
CHATBOT_SYSTEM = """You are a friendly customer support assistant for Acme Corp.
Answer questions about our products and policies.
If you do not know the answer, say so honestly.
Never discuss competitors or topics outside Acme products."""

# Data extractor: precise, structured
EXTRACTOR_SYSTEM = """You are a data extraction engine.
Extract the requested fields from the input text.
Respond with valid JSON only. No commentary."""

# Coding assistant: technical, actionable
CODER_SYSTEM = """You are an expert Python developer.
When asked to write code, produce clean, well-documented, production-ready code.
Include type hints and docstrings.
If the request is ambiguous, state your assumptions."""
```

## Common Mistakes

1. **Stuffing everything into one giant prompt** -- Break complex tasks into multiple LLM calls (decomposition).
2. **Not testing prompts with edge cases** -- The first input that works is not proof the prompt is robust.
3. **Using vague instructions** -- "Be helpful" is useless. "Respond with a JSON object containing exactly three keys: name, age, city" is actionable.
4. **Forgetting to handle parsing failures** -- The model will occasionally produce malformed output. Always have a fallback.
5. **Ignoring token limits** -- Few-shot examples consume tokens. If your examples plus input exceed the context window, the call fails or the model's output gets truncated.
