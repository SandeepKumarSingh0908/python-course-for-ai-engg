## Section 1: What Are Embeddings?

An **embedding** is a list of floating-point numbers (a vector) that represents the meaning of a piece of text. Similar texts produce similar vectors.

```
"happy cat"  -> [0.12, -0.34, 0.56, ..., 0.78]   (1536 dimensions)
"joyful kitten" -> [0.11, -0.32, 0.55, ..., 0.79]   (very similar!)
"stock market"  -> [-0.45, 0.67, -0.12, ..., 0.33]   (very different)
```

**Key properties:**
- Dimensionality is fixed per model (e.g., 1536 for OpenAI `text-embedding-3-small`)
- Nearby vectors in this space have similar meanings
- The vectors themselves are not human-readable
- You compare vectors using distance metrics like cosine similarity

### Batch Embedding Helper

```python
from openai import OpenAI


def embed_texts(
    texts: list[str],
    model: str = "text-embedding-3-small",
    batch_size: int = 100,
) -> list[list[float]]:
    """Embed a list of texts in batches to respect API limits."""
    client = OpenAI()
    all_embeddings = []

    for i in range(0, len(texts), batch_size):
        batch = texts[i : i + batch_size]
        response = client.embeddings.create(model=model, input=batch)
        batch_embeddings = [item.embedding for item in response.data]
        all_embeddings.extend(batch_embeddings)

    return all_embeddings
```

## Section 3: Similarity Metrics

### Cosine Similarity

Measures the angle between two vectors. Ranges from -1 (opposite) to 1 (identical). Most common for text embeddings.

```python
import numpy as np


def cosine_similarity(a: list[float], b: list[float]) -> float:
    """Compute cosine similarity between two vectors."""
    a_arr = np.array(a)
    b_arr = np.array(b)
    return float(np.dot(a_arr, b_arr) / (np.linalg.norm(a_arr) * np.linalg.norm(b_arr)))


# Example
sim = cosine_similarity(embedding_1, embedding_2)
print(f"Similarity: {sim:.4f}")  # close to 1.0 = similar meaning
```

### Other Metrics

```python
def euclidean_distance(a: list[float], b: list[float]) -> float:
    """L2 distance. Smaller = more similar."""
    return float(np.linalg.norm(np.array(a) - np.array(b)))


def dot_product(a: list[float], b: list[float]) -> float:
    """Dot product similarity. Larger = more similar.
    Use when embeddings are already normalized."""
    return float(np.dot(a, b))
```

**When to use which:**
| Metric | Best for | Range |
|---|---|---|
| Cosine similarity | General text similarity | -1 to 1 |
| Euclidean (L2) | When magnitude matters | 0 to infinity |
| Dot product | Normalized embeddings (faster) | -1 to 1 |

## Section 4: ChromaDB

ChromaDB is an open-source, easy-to-use vector database perfect for prototyping and small-to-medium workloads.

```bash
pip install chromadb
```

### Create a Collection and Add Documents

```python
import chromadb

# In-memory client (data lost on restart)
client = chromadb.Client()

# Or persistent client (data saved to disk)
# client = chromadb.PersistentClient(path="./chroma_data")

# Create a collection -- ChromaDB generates embeddings automatically
# using its built-in model (all-MiniLM-L6-v2)
collection = client.create_collection(
    name="python_docs",
    metadata={"description": "Python documentation snippets"},
)

# Add documents
collection.add(
    ids=["doc1", "doc2", "doc3", "doc4"],
    documents=[
        "Lists in Python are mutable sequences used to store collections of items.",
        "Dictionaries map keys to values and provide O(1) average lookup time.",
        "The asyncio module provides infrastructure for writing concurrent code.",
        "NumPy arrays are fixed-size, homogeneous, and much faster than Python lists.",
    ],
    metadatas=[
        {"topic": "data-structures", "level": "beginner"},
        {"topic": "data-structures", "level": "beginner"},
        {"topic": "concurrency", "level": "intermediate"},
        {"topic": "scientific", "level": "intermediate"},
    ],
)

print(f"Collection size: {collection.count()}")
```

### Query the Collection

```python
results = collection.query(
    query_texts=["How do I store key-value pairs in Python?"],
    n_results=2,
)

for i, doc in enumerate(results["documents"][0]):
    distance = results["distances"][0][i]
    doc_id = results["ids"][0][i]
    print(f"[{doc_id}] (distance={distance:.4f}) {doc}")
```

### Filter with Metadata

```python
results = collection.query(
    query_texts=["fast array operations"],
    n_results=3,
    where={"topic": "scientific"},  # only search scientific docs
)
```

## Section 5: FAISS for Fast Similarity Search

FAISS (Facebook AI Similarity Search) is optimized for speed and scale. It handles millions of vectors efficiently.

```bash
pip install faiss-cpu
```

### Basic FAISS Index

```python
import numpy as np
import faiss

# Generate some sample embeddings (normally you'd get these from an API)
dimension = 384
num_vectors = 1000

# Random normalized vectors for demonstration
np.random.seed(42)
vectors = np.random.randn(num_vectors, dimension).astype("float32")
faiss.normalize_L2(vectors)  # normalize for cosine similarity

# Build a flat (exact) index
index = faiss.IndexFlatIP(dimension)  # IP = Inner Product (cosine for normalized vectors)
index.add(vectors)

print(f"Index contains {index.ntotal} vectors")

# Query: find the 5 nearest neighbors
query = np.random.randn(1, dimension).astype("float32")
faiss.normalize_L2(query)

distances, indices = index.search(query, k=5)

print(f"Nearest neighbor indices: {indices[0]}")
print(f"Similarity scores: {distances[0]}")
```

### FAISS with Real Text Embeddings

```python
from sentence_transformers import SentenceTransformer
import faiss
import numpy as np

# Prepare data
documents = [
    "Python lists are mutable sequences.",
    "Dictionaries provide O(1) lookup.",
    "NumPy arrays are faster than lists.",
    "FastAPI is great for building APIs.",
    "Pandas DataFrames handle tabular data.",
]

# Generate embeddings
model = SentenceTransformer("all-MiniLM-L6-v2")
embeddings = model.encode(documents).astype("float32")
faiss.normalize_L2(embeddings)

# Build index
dimension = embeddings.shape[1]
index = faiss.IndexFlatIP(dimension)
index.add(embeddings)

# Search
query_text = "How do I work with tabular data?"
query_embedding = model.encode([query_text]).astype("float32")
faiss.normalize_L2(query_embedding)

distances, indices = index.search(query_embedding, k=3)

print("Results:")
for rank, (idx, score) in enumerate(zip(indices[0], distances[0])):
    print(f"  {rank + 1}. [{score:.4f}] {documents[idx]}")
```

### Saving and Loading FAISS Indexes

```python
# Save
faiss.write_index(index, "my_index.faiss")

# Load
loaded_index = faiss.read_index("my_index.faiss")
print(f"Loaded index with {loaded_index.ntotal} vectors")
```

### ChromaDB vs FAISS

| Feature | ChromaDB | FAISS |
|---|---|---|
| Setup | Simple Python API | Lower-level, more manual |
| Document storage | Built-in (text + metadata) | Vectors only (store docs separately) |
| Auto-embedding | Yes | No |
| Scale | Thousands to low millions | Millions to billions |
| Persistence | Built-in | Manual save/load |
| Best for | Prototyping, RAG apps | Large-scale production search |

## Common Mistakes

1. **Not normalizing embeddings before cosine similarity** -- FAISS `IndexFlatIP` assumes normalized vectors. Call `faiss.normalize_L2()` first.
2. **Mixing embedding models** -- If you index with `text-embedding-3-small`, you must query with the same model. Dimensions and semantic spaces differ between models.
3. **Ignoring embedding costs** -- Embedding 10,000 documents with OpenAI costs real money. Use sentence-transformers for development and testing.
4. **Forgetting to store the original text** -- FAISS only stores vectors. You need a separate mapping from index position to original document.
5. **Using exact search at scale** -- `IndexFlatIP` checks every vector. For millions of documents, use approximate indexes like `IndexIVFFlat` or `IndexHNSWFlat`.
