## Section 1: The Basics -- try / except / else / finally

```python
try:
    result = int(input("Enter a number: "))
except ValueError:
    print("That was not a valid integer.")
else:
    # Runs ONLY if no exception was raised
    print(f"You entered {result}")
finally:
    # Runs ALWAYS, whether or not an exception occurred
    print("Input phase complete.")
```

### Execution Flow

| Scenario | try | except | else | finally |
|----------|-----|--------|------|---------|
| No error | runs | skipped | runs | runs |
| Error caught | runs (partially) | runs | skipped | runs |
| Error NOT caught | runs (partially) | skipped | skipped | runs, then error propagates |

### Catching Multiple Exception Types

```python
try:
    data = {"a": 1}
    value = data["b"]
except KeyError:
    print("Key not found")
except (TypeError, ValueError) as e:
    print(f"Type or value problem: {e}")
except Exception as e:
    # Catch-all -- use sparingly
    print(f"Unexpected error: {e}")
```

**Rule of thumb:** Catch the most specific exception you can. A bare `except:` or `except Exception:` at the top level is acceptable for logging, but burying it inside business logic hides real bugs.

## Section 2: Common Built-in Exceptions

| Exception | When It Fires | Typical AI/ML Scenario |
|-----------|---------------|----------------------|
| `ValueError` | Wrong value for the type | `int("abc")`, invalid hyperparameter |
| `TypeError` | Wrong type passed | Passing a list where a tensor is expected |
| `KeyError` | Dict key missing | Missing column in a data record |
| `IndexError` | List index out of range | Batch index exceeds dataset length |
| `FileNotFoundError` | File does not exist | Missing checkpoint or dataset file |
| `AttributeError` | Object has no such attribute | Calling `.predict()` on an untrained model |
| `RuntimeError` | Generic runtime problem | CUDA out of memory |
| `StopIteration` | Iterator exhausted | Data loader reaches end of epoch |
| `ImportError` | Module not found | Optional dependency not installed |

## Section 3: Custom Exception Classes

For any non-trivial project, define your own exceptions. They make error handling self-documenting.

```python
class DataPipelineError(Exception):
    """Base exception for data pipeline issues."""
    pass

class SchemaValidationError(DataPipelineError):
    """Raised when input data does not match the expected schema."""
    def __init__(self, field: str, expected: str, got: str):
        self.field = field
        self.expected = expected
        self.got = got
        super().__init__(
            f"Field '{field}': expected {expected}, got {got}"
        )

class MissingFieldError(DataPipelineError):
    """Raised when a required field is absent."""
    def __init__(self, field: str):
        self.field = field
        super().__init__(f"Required field missing: '{field}'")
```

Usage:

```python
def validate_record(record: dict) -> None:
    required = ["text", "label"]
    for field in required:
        if field not in record:
            raise MissingFieldError(field)

    if not isinstance(record["label"], int):
        raise SchemaValidationError(
            "label", "int", type(record["label"]).__name__
        )

try:
    validate_record({"text": "hello"})
except MissingFieldError as e:
    print(f"Validation failed: {e}")
    print(f"Missing field: {e.field}")
```

The hierarchy lets callers catch at the granularity they want: catch `MissingFieldError` for a specific case or `DataPipelineError` for anything pipeline-related.

## Section 4: Exception Chaining -- `raise ... from ...`

When you catch one exception and raise a different one, Python can preserve the original traceback.

```python
import json

def load_config(path: str) -> dict:
    try:
        with open(path, encoding="utf-8") as f:
            return json.load(f)
    except json.JSONDecodeError as e:
        raise DataPipelineError(
            f"Invalid JSON in config file: {path}"
        ) from e
    except FileNotFoundError as e:
        raise DataPipelineError(
            f"Config file not found: {path}"
        ) from e
```

When this raises, the traceback shows **both** exceptions:

```
DataPipelineError: Invalid JSON in config file: config.json

The above exception was the direct cause of the following exception:

json.decoder.JSONDecodeError: Expecting value: line 3 column 5 ...
```

Use `from e` when you want callers to see the root cause. Use `from None` to suppress the chained traceback intentionally (rare).

## Section 5: EAFP vs LBYL

Python has two philosophies for dealing with potential errors.

### LBYL -- Look Before You Leap

Check conditions before acting.

```python
# LBYL style
if "temperature" in config:
    temp = config["temperature"]
else:
    temp = 0.7
```

### EAFP -- Easier to Ask Forgiveness than Permission

Try the operation and handle failure.

```python
# EAFP style (preferred in Python)
try:
    temp = config["temperature"]
except KeyError:
    temp = 0.7
```

**When to use which:**

| Style | Best for |
|-------|----------|
| EAFP | Dict access, file operations, attribute checks -- anything where the happy path is the common case |
| LBYL | Expensive operations where checking is cheaper than failing (e.g., checking if GPU memory is sufficient before allocating a tensor) |

Python's culture strongly favors EAFP. The `dict.get(key, default)` method is actually EAFP wrapped in a convenience method.

## Section 6: Worked Example -- Resilient Data Loader

```python
import csv
import json
import logging
from pathlib import Path

logging.basicConfig(level=logging.WARNING)
logger = logging.getLogger(__name__)

class DataLoadError(Exception):
    """Raised when the data loader cannot process a file."""
    pass

def load_dataset(path: str, skip_bad_rows: bool = True) -> list[dict]:
    """Load a CSV dataset, converting numeric fields.

    Args:
        path: Path to CSV file.
        skip_bad_rows: If True, log and skip bad rows.
                       If False, raise on first bad row.

    Returns:
        List of validated record dicts.
    """
    file_path = Path(path)
    if not file_path.exists():
        raise DataLoadError(f"Dataset not found: {path}")

    records = []
    skipped = 0

    try:
        with open(file_path, encoding="utf-8") as f:
            reader = csv.DictReader(f)
            for i, row in enumerate(reader, start=2):  # row 1 is header
                try:
                    record = {
                        "text": row["text"].strip(),
                        "label": int(row["label"]),
                    }
                    if not record["text"]:
                        raise ValueError("Empty text field")
                    records.append(record)
                except (KeyError, ValueError) as e:
                    if skip_bad_rows:
                        logger.warning("Row %d skipped: %s", i, e)
                        skipped += 1
                    else:
                        raise DataLoadError(
                            f"Bad data at row {i}: {e}"
                        ) from e
    except UnicodeDecodeError as e:
        raise DataLoadError(f"Encoding error in {path}: {e}") from e

    if skipped:
        logger.warning("Total rows skipped: %d / %d", skipped, skipped + len(records))

    return records

# Usage
try:
    data = load_dataset("training.csv")
    print(f"Loaded {len(data)} records")
except DataLoadError as e:
    print(f"Failed to load dataset: {e}")
```

Key patterns: nested try/except for row-level vs file-level errors, a `skip_bad_rows` flag to let the caller decide strictness, and custom exceptions for clear error reporting.

## Lab: Build a Retry Decorator

Network calls to ML model APIs fail intermittently. Build a decorator that retries a function a configurable number of times with exponential backoff.

### Requirements

**1. Parameters**
The decorator takes `max_retries` (default 3) and `base_delay` (default 1.0 seconds).

**2. Exponential backoff**
On each retry, the delay doubles: 1s, 2s, 4s, etc.

**3. Exhaustion**
If all retries are exhausted, raise the last exception.

**4. Logging**
Log each retry attempt.

**5. Selective retry**
Only retry on exceptions listed in a `retryable_exceptions` tuple.

            # TODO: implement retry logic
            # - Loop up to max_retries + 1 (first attempt + retries)
            # - On a retryable exception, log and sleep
            # - On the last attempt, let the exception propagate
            # - Double the delay each retry

## Common Mistakes

| Mistake | Fix |
|---------|-----|
| Bare `except:` catching everything | Always specify exception types; at minimum use `except Exception:` |
| Catching too broadly and silencing errors | Catch specific exceptions; re-raise or log unexpected ones |
| Using exceptions for normal control flow | Exceptions should be for exceptional cases, not replacing `if` checks |
| Forgetting `from e` when re-raising | Use `raise NewError(...) from e` to preserve the traceback chain |
| Empty `except` blocks (`pass`) | At minimum, log the error; silent failures are debugging nightmares |
| Modifying state before a try block without cleanup | Put cleanup in `finally` or use context managers |

### Solution 1: Retry Decorator

```python
import time
import logging
import functools

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)


def retry(
    max_retries: int = 3,
    base_delay: float = 1.0,
    retryable_exceptions: tuple = (Exception,),
):
    """Decorator that retries a function with exponential backoff."""
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            delay = base_delay
            last_exception = None
            for attempt in range(max_retries + 1):
                try:
                    return func(*args, **kwargs)
                except retryable_exceptions as e:
                    last_exception = e
                    if attempt < max_retries:
                        logger.info(
                            "Attempt %d/%d failed: %s. Retrying in %.1fs...",
                            attempt + 1, max_retries + 1, e, delay,
                        )
                        time.sleep(delay)
                        delay *= 2
                    else:
                        logger.error(
                            "All %d attempts failed. Last error: %s",
                            max_retries + 1, e,
                        )
                        raise
                except Exception:
                    # Non-retryable exception — propagate immediately
                    raise
            raise last_exception  # unreachable, but makes linters happy
        return wrapper
    return decorator


# Test
call_count = 0

@retry(max_retries=3, base_delay=0.1, retryable_exceptions=(ConnectionError,))
def flaky_api_call(prompt: str) -> str:
    global call_count
    call_count += 1
    if call_count < 3:
        raise ConnectionError("Server unavailable")
    return f"Response to: {prompt}"


result = flaky_api_call("Summarize this text")
print(result)
assert call_count == 3
assert result == "Response to: Summarize this text"
print("Retry test passed!")


@retry(max_retries=3, base_delay=0.1, retryable_exceptions=(ConnectionError,))
def bad_input():
    raise ValueError("Invalid input")


try:
    bad_input()
    assert False, "Should have raised ValueError"
except ValueError:
    print("Non-retryable exception propagated correctly!")
```

### Stretch Goal: Retry with Jitter

```python
import random

def retry_with_jitter(
    max_retries: int = 3,
    base_delay: float = 1.0,
    retryable_exceptions: tuple = (Exception,),
):
    """Retry decorator with exponential backoff and random jitter."""
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            delay = base_delay
            for attempt in range(max_retries + 1):
                try:
                    return func(*args, **kwargs)
                except retryable_exceptions as e:
                    if attempt < max_retries:
                        jitter = random.uniform(0, delay * 0.3)
                        sleep_time = delay + jitter
                        logger.info(
                            "Attempt %d/%d failed. Retrying in %.2fs (with jitter)...",
                            attempt + 1, max_retries + 1, sleep_time,
                        )
                        time.sleep(sleep_time)
                        delay *= 2
                    else:
                        raise
                except Exception:
                    raise
        return wrapper
    return decorator
```
